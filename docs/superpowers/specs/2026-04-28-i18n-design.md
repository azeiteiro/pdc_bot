# i18n Integration Design

**Date:** 2026-04-28
**Status:** Approved
**Scope:** Add multi-language support to the expense conversation using @grammyjs/i18n

## Overview

Add internationalization to the Telegram bot's `/expense` conversation, supporting English and European Portuguese. Language will be auto-detected from the user's Telegram settings with English as the default fallback.

## Goals

- Enable Portuguese and English translations for the expense conversation
- Auto-detect user language from Telegram's `language_code`
- Maintain existing conversation logic and flow
- Use industry-standard i18n tooling (@grammyjs/i18n with Fluent)
- Keep implementation simple and testable

## Non-Goals

- Translating other commands (lineup, help, about, admin commands) - future work
- Translating command descriptions in Telegram's UI - future work
- Supporting manual language switching - not needed for initial implementation
- Supporting additional languages beyond EN and PT - can add later

## Requirements

### Functional Requirements

1. **Language Detection**
   - Auto-detect from `ctx.from.language_code`
   - Map `pt`, `pt-BR`, `pt-PT` → `pt` locale (European Portuguese)
   - Default to `en` for all other languages

2. **Supported Languages**
   - English (en) - primary/default
   - Portuguese (pt) - European Portuguese, NOT Brazilian Portuguese

3. **Scope**
   - All text in `/expense` conversation:
     - Prompts (description, amount, name, date)
     - Validation errors
     - Confirmation messages
     - Keyboard button labels
     - Success/error messages
     - Google Sheets error messages

4. **Date Format**
   - Change from `YYYY-MM-DD` to `DD-MM-YYYY`
   - Universal format (same for both languages)
   - Accept "today" keyword in both languages

### Technical Requirements

1. **Type Safety**
   - Extend `BotContext` with `I18nFlavor`
   - Full TypeScript support for `ctx.t()`

2. **Middleware Order**
   - i18n middleware must run before conversations middleware
   - Maintain existing hydrate, session, conversations plugins

3. **File Organization**
   - Fluent translation files in `src/locales/`
   - One `.ftl` file per language
   - Use kebab-case for translation keys
   - Namespace keys with `expense-` prefix

4. **Testing**
   - Update existing tests to mock `ctx.t()`
   - Manual testing with both language codes
   - Verify translation completeness (both .ftl files have same keys)

## Architecture

### Middleware Stack

```
bot.use(hydrate())          // Existing
bot.use(i18n)               // NEW - must come before conversations
bot.use(session())          // Existing
bot.use(conversations())    // Existing
```

### Type System

```typescript
import { I18nFlavor } from '@grammyjs/i18n';

export type BotContext = HydrateFlavor<Context> &
  SessionFlavor<SessionData> &
  ConversationFlavor<Context> &
  I18nFlavor;  // NEW

export type BotConversation = Conversation<BotContext>;
```

### i18n Configuration

```typescript
import { I18n } from '@grammyjs/i18n';

const i18n = new I18n({
  defaultLocale: 'en',
  directory: 'src/locales',
  useSession: false,
  localeNegotiator: (ctx) => {
    const userLang = ctx.from?.language_code;

    // Map all Portuguese variants to pt (European Portuguese)
    if (userLang?.startsWith('pt')) return 'pt';

    // Default to English for everything else
    return 'en';
  }
});
```

**Note:** Even though Telegram reports `pt-BR` for Portuguese speakers, our `pt.ftl` file will contain European Portuguese translations, which is preferred in Portugal.

## Translation Keys Structure

Translation keys use kebab-case with `expense-` prefix:

```ftl
# Prompts
expense-enter-description = ...
expense-enter-amount = ...
expense-enter-name = ...
expense-enter-date = ...

# Validation
expense-invalid-amount = ...
expense-invalid-date = ...

# Keyboard buttons
expense-edit-title = ...
expense-edit-name = ...
expense-edit-value = ...
expense-edit-date = ...
expense-cancel = ...
expense-accept = ...

# Confirmation
expense-confirmation = ...

# Status messages
expense-success = ...
expense-cancelled = ...
expense-sheets-error = ...
expense-no-spreadsheet = ...

# Usage help
expense-usage = ...
```

### Variable Interpolation

Fluent uses `{$variableName}` syntax:

```ftl
expense-confirmation =
    Title: {$title}
    Amount: €{$amount}
    Name: {$name}
    Date: {$date}
```

Usage:
```typescript
ctx.t('expense-confirmation', {
  title: 'Lunch',
  amount: 10.50,
  name: 'Daniel',
  date: '28-04-2026'
})
```

## Implementation Details

### Date Formatting Changes

**Current format:** `YYYY-MM-DD` (ISO 8601)
**New format:** `DD-MM-YYYY` (European standard)

**Helper function:**
```typescript
const formatDate = (date: Date): string => {
  const day = String(date.getDate()).padStart(2, '0');
  const month = String(date.getMonth() + 1).padStart(2, '0');
  const year = date.getFullYear();
  return `${day}-${month}-${year}`;
};
```

**Validation regex:**
```typescript
// Old: /^\d{4}-\d{2}-\d{2}$/
// New: /^\d{2}-\d{2}-\d{4}$/
```

### Conversation Pattern

**Before:**
```typescript
await ctx.reply('Please provide a description for the expense');
```

**After:**
```typescript
await ctx.reply(ctx.t('expense-enter-description'));
```

**With keyboard:**
```typescript
const keyboard = new Keyboard()
  .text(ctx.t('expense-edit-title'))
  .text(ctx.t('expense-edit-name'))
  .row()
  .text(ctx.t('expense-edit-value'))
  .text(ctx.t('expense-edit-date'))
  .row()
  .text(ctx.t('expense-cancel'))
  .text(ctx.t('expense-accept'))
```

All hardcoded strings in `addExpenseScene.ts` will be replaced with `ctx.t()` calls.

## Testing Strategy

### Manual Testing

1. Test with English user (`language_code: en`)
   - Run through full conversation
   - Test quick insert: `/expense Lunch 10.50`
   - Test interactive flow
   - Test all edit flows
   - Test cancellation

2. Test with Portuguese user (`language_code: pt` or `pt-BR`)
   - Same test cases as above
   - Verify European Portuguese translations

3. Test with unsupported language (`language_code: es`)
   - Should default to English
   - Verify fallback works

4. Test edge cases:
   - User with no language_code set
   - Invalid amounts
   - Invalid dates
   - Google Sheets errors

### Unit Testing

Update `addExpenseScene.test.ts` to mock i18n:

```typescript
const mockCtx = {
  t: (key: string, vars?: any) => key,  // Returns key for assertions
  // ... other context properties
};
```

Tests verify:
- Conversation flow logic (not translated text)
- Correct translation keys are called
- Variables are passed correctly

### Translation Validation

Before merging:
- Manually verify `en.ftl` and `pt.ftl` have identical keys
- Load both files in bot startup to catch syntax errors
- Check for missing translations (i18n plugin will warn)

## Error Handling

All error scenarios will be internationalized:

1. **Invalid amount** - `expense-invalid-amount`
2. **Invalid date** - `expense-invalid-date`
3. **Google Sheets API error** - `expense-sheets-error`
4. **Missing spreadsheet ID** - `expense-no-spreadsheet`
5. **Success confirmation** - `expense-success`
6. **Cancellation** - `expense-cancelled`

Error messages will be user-friendly in both languages. Technical details remain in logs (English only).

## Linting and Validation

- ESLint will continue to lint only `.js` and `.ts` files
- `.ftl` files are not linted by ESLint (they're data files, not code)
- Add `src/locales/*.ftl` to `.prettierignore`
- Runtime validation: `@grammyjs/i18n` will throw errors if `.ftl` syntax is invalid
- Future enhancement: could add `@fluent/syntax` for CI validation

## Migration Path

This is the first step in full i18n support:

1. **Phase 1 (this spec):** Expense conversation only
2. **Phase 2 (future):** General commands (lineup, info, help, about)
3. **Phase 3 (future):** Admin commands
4. **Phase 4 (future):** Command descriptions in Telegram UI
5. **Phase 5 (future):** Additional languages if needed

Each phase can be implemented independently.

## Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| i18n context not available in conversations | High | Use type-safe I18nFlavor, test early |
| Missing translations | Medium | Manual key comparison, runtime warnings |
| Date format confusion | Low | Clear error messages, examples in prompts |
| Portuguese users expect pt-BR | Low | Document that we use pt-PT; adjust if needed |
